# JAQAIYM: сайт и конструктор заявки

Сайт корпусной мебели на заказ (Астана и Алматы), боевой адрес https://jaqaiym.kz. Клиент заполняет анкету из 4 шагов или задаёт быстрый вопрос,
заявка (с фото и PDF) приходит команде в Telegram. Сайт на двух языках: русский и казахский.

Боевой сервер заявок написан на PHP (общий хостинг ps.kz: Plesk, PHP 8.3, cron, без Python и SSH). Статика собирается из `public/`.
Прежний сервер на Python удалён (метка `legacy-python-server` в git возвращает его при необходимости).

## Структура

| Путь | Что это |
| --- | --- |
| `public/` | Сайт: `index.html`, анкета `request/index.html`, `privacy.html`, `css/`, `js/`, `fonts/`, `img/`, `i18n/` (тексты ru и kk), `schema.json`, `site.json` |
| `public/schema.json` | Единый словарь ответов и правила обязательных полей (раздел `required`): читают и анкета, и сервер, и тесты |
| `public/site.json` | Контакты, версия политики, адрес сайта, данные оператора, токены подтверждения в поисковиках |
| `render.py`, `seo.py` | Сборка страниц из шаблонов (подстановка `{{ключей}}`), теги для поисковиков и соцсетей, `robots.txt`, `sitemap.xml` |
| `php/src/` | Сервер заявок: приём и файлы, Telegram, админка (классы `Jq\`, без сторонних библиотек) |
| `php/httpdocs/` | Что кладётся в корень сайта: `api/index.php` (единственный PHP-файл) и `.htaccess` |
| `php/bin/cron.php` | Задача по расписанию: повтор отправок, очистка файлов, срок хранения заявок |
| `php/config.env.example` | Образец настроек (`config.env` создаёт владелец, в git его нет) |
| `tools/build_php.py`, `tools/build_static.py` | Сборка: `dist/httpdocs` (сайт) и `dist/jaqaiym-private` (код сервера вне корня сайта); демо для GitHub Pages |
| `tools/publish_deploy.sh` | Выкладка сборки в ветку `deploy` (автодеплой) |
| `tools/gen_i18n.py`, `tools/legal_text.py` | Тексты сайта (один список для ru и kk) и политика конфиденциальности |
| `tools/make_config.py`, `tools/make_admin_path.py` | Боевой `config.env` с новыми секретами и непубличный адрес админки: запускаются на вашем компьютере |
| `tools/make_og_image.py`, `tools/fetch_fonts.py`, `tools/telegram_setup.py` | Превью для соцсетей, шрифты, диагностика Telegram-бота |
| `tools/test_*.py`, `tools/testkit.py`, `tools/php_harness.py`, `tools/contract.py`, `tools/check.sh` | Автотесты и общая обвязка |
| `brand-source/` | Исходники бренда (на сайт не попадают) |
| `docs/` | Демо для GitHub Pages (генерируется) |
| `legal/` | Отчёт по проверке политики на соответствие закону |

## Локальная разработка

```bash
python3 tools/build_php.py --noindex --out dist
printf 'ADMIN_TOKEN=%s\nADMIN_PATH=/admin/dev-secret-path\n' "$(python3 -c 'import secrets; print(secrets.token_urlsafe(24))')" > dist/jaqaiym-private/config.env
php -S 127.0.0.1:8123 -t dist/httpdocs php/dev-router.php
```

Сайт: http://127.0.0.1:8123, админка: `/admin/dev-secret-path` (пароль в `dist/jaqaiym-private/config.env`). Без `TELEGRAM_BOT_TOKEN` уведомления пишутся в `dist/jaqaiym-private/data/outbox.log`.
**Не кладите в этот `config.env` боевой токен бота:** локальный сервер вызывает Telegram по-настоящему. Для разработки заведите отдельного тестового бота у `@BotFather`.

Все проверки одной командой: `bash tools/check.sh` (синтаксис, тексты, тесты сервера, безопасности, поисковиков, выкладки; настоящий Telegram не нужен).
Ту же команду выполняет CI на каждом `push` (PHP 8.3, как на хостинге).

## Языки

Русский (`/`, `/request/`) и казахский (`/kk/`, `/kk/request/`), переключатель в шапке. Тексты лежат в `tools/gen_i18n.py` (русский и казахский рядом),
после правки запустите `python3 tools/gen_i18n.py`: он обновит `public/i18n/*.json`. Подписи вариантов ответа: `schema.json` (рус.) и блок `schema` в `kk.json`.
Язык клиента сохраняется в заявке, карточка для команды всегда на русском. **Казахские тексты нужно показать носителю языка.**

## Обязательные поля анкеты

Правила лежат в `public/schema.json` (раздел `required`) и одинаково применяются в анкете (`wizard.js`) и на сервере; `tools/contract.py` проверяет это тестами.
- Шаг 1: тип заказа, где стоит мебель, город (только Астана и Алматы).
- Шаг 2: внешний вид и вопросы по типу заказа (кухня: планировка, верхние шкафы, остров, техника; шкаф: тип, двери, что хранить; прочая мебель: назначение; бизнес: тип объекта, задача, количество).
- Шаг 3: размеры или отметка «Не знаю размеры»; для «Другое» описание. Фото, бюджет, срок и комментарии необязательны.
- Шаг 4: имя, телефон и согласие на обработку данных.
Везде есть вариант «не знаю», поэтому клиента ничего не блокирует. Добавили поле или тип заказа: правьте `schema.json`, тесты проверят, что сервер принимает заявку с ответом и отклоняет без него.

## Боевой сайт на ps.kz

**Первая установка (уже сделана).** Сборка кладётся в корень домена: `jaqaiym-private` рядом с `httpdocs`, а не внутри. Дальше:
1. Секреты создаёт скрипт на вашем компьютере: `python3 tools/make_config.py` (пароль админки, код подписки, токен бота из локального `.env`; файл появится на рабочем столе, значения на экран не выводятся).
   Загрузите его в `jaqaiym-private` как `config.env` (права 600) и удалите файл с компьютера. Затем `python3 tools/make_admin_path.py` печатает строку `ADMIN_PATH=...` для конца `config.env`.
2. Админка включается только при `ADMIN_TOKEN` (от 16 символов) и `ADMIN_PATH` вида `/admin/<секрет>`. Иначе она отключена (503), а не открыта по умолчанию. Стандартный `/admin` отвечает 404.
3. Let's Encrypt для jaqaiym.kz и www; PHP 8.3, `post_max_size` не меньше 12M; планировщик Plesk: «Запустить PHP-скрипт» `jaqaiym-private/bin/cron.php` раз в минуту.
4. В админке нажмите «подключить вебхук» (без него бот не увидит `/join`). Блок «Состояние сервера» покажет версию PHP, расширения, лимиты и адрес посетителя.
5. Резервные копии: включите в Plesk копирование всего домена, включая `jaqaiym-private/data` (база заявок). ImunifyAV для сайта в консоли ps.kz по умолчанию не подключён.

**Автодеплой.** Пуш в `main` запускает CI: если проверки зелёные, задание `deploy` собирает сайт и кладёт его в ветку `deploy` (`tools/publish_deploy.sh`: обычный коммит,
без `--force`; секреты, базы и данные в ветку не попадают, это проверяется). Plesk (Сайты и домены → Git, репозиторий `jaqaiym-site.git`, ветка `deploy`, режим «Автоматически», путь `/`)
получает вебхук GitHub и раскладывает файлы: `httpdocs/` в корень сайта, `jaqaiym-private/` рядом. `config.env`, `data/` и `logs/` в ветке нет, поэтому выкладка их не трогает; удалённые в репозитории файлы удаляются и на сайте.
- Откат: `git revert` плохого коммита и пуш. Вручную: Plesk → Git → «Получить сейчас» / «Развернуть сейчас».
- Тот, кто может писать в `main`, управляет сайтом: включите двухфакторный вход в аккаунте GitHub и не раздавайте права записи.
- Установка автодеплоя с нуля: репозиторий Git в Plesk с URL GitHub и веткой `deploy`, путь `/`, вебхук Plesk (Настройки репозитория) вписать в GitHub (Settings → Webhooks, событие push).

**Поисковики и соцсети.** Теги собирает `seo.py`: `canonical`, `hreflang` (ru, kk, x-default), Open Graph и Twitter-карточки (`img/brand/og.jpg` 1200×630, пересборка `python3 tools/make_og_image.py`),
разметка schema.org (Organization и WebSite, без телефона, адреса и БИН), `robots.txt`, `sitemap.xml`. Анкета остаётся с `noindex`.
Индексация включается переменной репозитория `SITE_INDEXING=true` (GitHub: Settings → Secrets and variables → Actions → Variables); без неё сайт закрыт (`noindex` и `Disallow: /`).
После смены переменной: Actions → tests → Run workflow. `www` перенаправляется на основной домен, `http` на `https` перенаправляет Plesk. Сайт подтверждён в Google Search Console и Яндекс Вебмастере (TXT-записи в DNS и метатег; удалять их нельзя).

## Безопасность

- Код, база, загруженные файлы и `config.env` лежат вне корня сайта и по ссылке недоступны; в корне один PHP-файл. Файлы данных создаются с правами только для владельца.
- Админка: пароль не короче 16 символов и непубличный адрес. Вход выдаёт cookie (HttpOnly, Secure, SameSite=Lax, 12 часов), изменения защищены токеном CSRF и проверкой Origin.
  Смена `ADMIN_TOKEN` и кнопка «Выйти» сразу отзывают все выданные cookie на сервере. Адрес админки секретный, но не как пароль (он есть в ссылках на заявки в Telegram и в истории браузера), поэтому пароль остаётся длинным и случайным.
- Перебор пароля: считаются только неудачные попытки и только с одного адреса (8 за 15 минут, IPv6 по сети /64). Общего счётчика нет, поэтому владельца снаружи не запереть.
- Загрузки: тип определяется по содержимому (JPG, PNG, WebP, PDF), на диске файлы лежат под случайными именами, лимит 10 МБ и квота диска; после отправки в Telegram файл удаляется.
- Заявки: типы и длины проверяются на сервере, SQL только через подготовленные запросы, текст клиента в сообщении команде сводится к одной строке, в админке всё экранируется. Вебхук Telegram принимает только запросы с секретным заголовком.
- Лимиты запросов по IP; в базе только необратимый хеш IP, не дольше суток. Страницы: CSP, HSTS, X-Frame-Options, nosniff, Permissions-Policy (`php/httpdocs/.htaccess`).
- Срок хранения: заявки без договора удаляются через `RETENTION_DAYS` (365) после последнего контакта, со статусом «Договор» остаются. Любую заявку можно удалить вручную в админке («удалить»): вместе с файлами и записями о них.
- Почта домена: SPF (`-all`), DKIM и DMARC (`_dmarc.jaqaiym.kz`: `p=quarantine`, `pct=100`) в DNS зоне ps.kz. Когда убедитесь, что вся ваша почта с домена проходит проверку, смените `p=quarantine` на `p=reject`.
- GitHub: ветка `main` защищена от принудительной перезаписи и удаления (Settings → Branches), включены сканирование секретов и защита при пуше. SSH на хостинге для подписки запрещён, сертификат обновляется автоматически, Plesk делает ежедневные резервные копии.
- Остаётся на владельце: сообщения с заявками лежат в чатах Telegram (бот не может удалить их спустя 48 часов), их чистят вручную.

## Telegram: заявки, фото и файлы

В чат приходит карточка заявки, затем фото альбомом и PDF документами. Файл удаляется с диска после того, как Telegram подтвердил получение **всеми** получателями. Сбой не дублирует уже доставленное:
повтор досылает недостающее (паузы 1 мин, 2, 4 … до часа, до 40 попыток; кнопка «повторить отправку» в админке). Заявка сначала сохраняется в базе, поэтому сбой Telegram её не теряет.
Диск ограничен `UPLOAD_QUOTA_MB` (500) и `MIN_FREE_MB` (150): при нехватке места загрузка файлов отключается, заявки принимаются. Файлы без заявки удаляются через сутки, неотправленные через 7 суток.

**Бот и получатели.** `@BotFather` → `/newbot` → токен (секрет). Придумайте секретный код подписки. В `config.env` задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_JOIN_CODE`, в админке подключите вебхук.
Сотрудник открывает ссылку подписки из блока «Telegram» в админке и нажимает «Start» (или пишет боту `/join КОД`); группа: добавить бота и написать `/join@имя_бота КОД`. Отписка: `/leave`, либо «отключить» в админке.
Общий чат с известным id можно задать в `TELEGRAM_CHAT_ID` (`python3 tools/telegram_setup.py` поможет найти id). Чаты, где бота заблокировали, отключаются сами.

## Демо на GitHub Pages

Публичное демо (только статика, заявки не принимаются, закрыто от индексации): `python3 tools/build_static.py /jaqaiym-site docs`, затем коммит и пуш. Pages раздаёт папку `docs/` ветки `main`.

## Юридические документы

- `tools/legal_text.py`: политика конфиденциальности (рус. и каз.) и согласие на обработку (раздел 8 той же страницы). Данные оператора: `public/site.json` и константы вверху файла.
- Когда политику утвердит юрист: `SHOW_DRAFT_NOTICE = False` в `tools/legal_text.py`, `python3 tools/gen_i18n.py`, новая `policy_version` в `public/site.json`. Раздел 5 обещает хранение данных в Казахстане (ps.kz): при смене хостинга пересмотрите.
- Отчёт о проверке политики по закону: `legal/proverka-politiki-2026-11-03.md`. Шрифты хранятся в `public/fonts` (`python3 tools/fetch_fonts.py`), сайт не обращается к серверам Google.

## Что ещё решить владельцам

- **Фото в блоке «Наши работы»** (кухни, шкафы, прихожие) по именам файлов сток, не ваши работы. Замените на свои до продвижения сайта.
- **Бюджет**: диапазоны в `schema.json → budget` черновые: утвердить или убрать блок. **Контакты**: проверьте телефон и WhatsApp в `public/site.json`.
- **Политика** помечена как черновик; **казахские тексты** требуют проверки носителем. Города: только Астана и Алматы (добавить: `schema.json → city` и `KK_SCHEMA.city` в `tools/gen_i18n.py`).
- Аналитика: события уже отправляются в `window.dataLayer` (`request_opened`, `step_completed`, `attachment_added`, `request_submitted`, `request_failed`, `quick_contact_*`), счётчик не подключён. Подключение потребует баннера согласия и правок политики.
