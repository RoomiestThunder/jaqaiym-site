# JAQAIYM — сайт и конструктор заявки (первый набросок)

Реализация этапов 1–3 из ТЗ (`JAQAIYM_конструктор_заявки_ТЗ_для_Санжара.md`): кликабельная анкета из 4 шагов,
реальный приём заявок и файлов, уведомление команде. Только стандартная библиотека Python, без сборки.

## Запуск

```bash
python3 server.py          # http://localhost:8123
```

- Сайт: `/`  ·  Анкета: `/request`  ·  Админка: `/admin?token=…` (токен печатается при старте и лежит в `data/admin_token.txt`).
- Заявки: `data/leads.db` (SQLite). Файлы: `data/uploads/` (не публичные; открываются только в админке по токену).
- Уведомления: без настроек пишутся в `data/outbox.log` (тестовый канал). Для Telegram задайте
  `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (общий чат команды, подключение: раздел «Telegram» ниже);
  сбой доставки не теряет заявку, сервер повторяет отправку раз в минуту (до 20 раз), причина ошибки видна в админке.

## Структура

| Путь | Что это |
| --- | --- |
| `public/index.html` | Главная: герой, категории, выполненные работы («Хочу похожее»), как это работает |
| `public/request/index.html` + `js/wizard.js` + `css/wizard.css` | Анкета: 4 шага, ветки кухня / шкаф / другая мебель / бизнес, черновик, файлы, итоги |
| `public/js/common.js` | Окно быстрой заявки («Написать нам», «Нужна помощь?»), аналитика, маска телефона |
| `public/schema.json` | Единый словарь ответов (читают и фронтенд, и сервер) |
| `public/site.json` | Телефон, WhatsApp, версия политики: **заглушки (TODO)**; подставляются в шаблоны и в `window.JQ_CONFIG` |
| `public/i18n/ru.json`, `kk.json` | Тексты сайта и анкеты на двух языках. Генерируются `python3 tools/gen_i18n.py` из одного списка |
| `server.py` | Рендер страниц с подстановкой `{{ключей}}` (`/` — русский, `/kk/…` — казахский), `POST /api/leads`, `POST /api/attachments`, `/admin` |

## Языки

Русский (`/`, `/request`) и казахский (`/kk/`, `/kk/request`), переключатель в шапке. Страницы собирает сервер: в HTML стоят `{{ключи}}`,
значения берутся из `public/i18n/<язык>.json`; подписи вариантов ответа в анкете: `schema.json` (рус.) + блок `schema` в `kk.json`.
Язык клиента сохраняется в заявке (`locale`), а карточка для команды всегда на русском. **Казахские тексты нужно показать носителю языка.**
Чтобы добавить язык: новый столбец в `tools/gen_i18n.py`, значение в `LANGS` и `PAGES` в `server.py`.

## Обязательные поля анкеты (клиент и сервер проверяют одинаково)

- Шаг 1: тип заказа, где стоит мебель, планировка кухни / тип шкафа / число объектов (по типу заказа), город (только Астана и Алматы).
- Шаг 2: внешний вид; кухня: верхние шкафы, остров и техника (да / нет / не знаю); шкаф: двери и что хранить; прочая мебель: назначение; бизнес: тип объекта и задача.
- Шаг 3: размеры (или отметка «Не знаю размеры»); бизнес: количество; «Другое»: описание. Фото, бюджет, срок и комментарии необязательны.
- Шаг 4: имя, телефон и согласие на обработку данных.
Во всех блоках есть вариант «не знаю / не определился», поэтому клиента это не блокирует. Правила сервера: `required_project_fields()` в `server.py`.

## Что уже соответствует ТЗ

- Вход из любой точки (§4): `?category=`, `?project_id=`, `utm_*`, `from` подставляются сами и не спрашиваются у клиента.
- «Не знаю размеры» → `dimensions_known=false`, размеры `null`; фото/файлы необязательны.
- Скрытые поля других категорий не отправляются, но сохраняются в черновике (смена «кухня → шкаф» ничего не стирает).
- Черновик в `localStorage` (7 дней, с `schema_version`), контакты только в `sessionStorage`.
- Экран «успех» только после ответа сервера `201/200` с `lead_id`; при ошибке сети/сервера ответы и файлы остаются, повтор не создаёт дубль (`submission_id`).
- Файлы: проверка типа по содержимому на сервере, лимиты 8 файлов / 10 МБ, прогресс загрузки, превью, удаление, повтор.
- Антиспам: поле-приманка + ограничение частоты по IP. Персональные данные не попадают в URL и аналитику.
- Нет неподтверждённых цен, сроков, скидок и «бесплатного 3D».

## Решения, которые нужно принять (ТЗ §12) и временные значения

- **Бюджет**: диапазоны в `schema.json → budget` — **черновые**. Утвердить или убрать блок целиком.
- **Контакты**: телефон и WhatsApp в `config.js` — заглушки.
- **Политика и согласие**: `privacy.html` — заглушка; `policyVersion` — `DRAFT`.
- **Города**: пока только Астана и Алматы (решение владельцев). Чтобы добавить город, допишите его в `schema.json → city`, `tools/gen_i18n.py → KK_SCHEMA.city` и перегенерируйте словари.
- **Размеры** вводятся в сантиметрах, хранятся в миллиметрах (`dimensions_mm`).
- **Фото в блоках «Примеры проектов»** (кухни, шкафы, прихожие) взяты из присланных папок; по именам файлов это сток (Unsplash/Pexels), не фото ваших работ. Перед публикацией замените на свои или оставьте подпись «примеры». Свои фото ЖК остались в блоке «Для бизнеса»; ваши прежние кухня и прихожая лежат в `public/img/own/`.
- Описания проектов в карточках описательные, без названий объектов.

## Дальше

1. Согласовать тексты и словарь, подключить настоящий канал уведомлений.
2. Деплой за HTTPS (нужен для доступа к файлам и согласия), хранилище файлов с истечением ссылок, резервное копирование `data/`.
3. Заменить встроенную админку на CRM/таблицу, если команде удобнее.
4. Аналитика: события уже отправляются в `window.dataLayer` (`request_opened`, `step_completed`, `attachment_added`, `request_submitted`, `request_failed`, `quick_contact_*`) — подключить счётчик.

## Публикация

**Демо на GitHub Pages** (только статика: сайт и анкета, но заявки не принимаются, в анкете виден баннер «Демонстрационная версия»):

```bash
python3 tools/build_static.py /jaqaiym-site docs   # пересобрать docs/ (префикс = имя репозитория)
git add -A && git commit -m "Обновить демо" && git push
```

Pages раздаёт папку `docs/` ветки `main`. Страницы помечены `noindex`, пока в них заглушки (телефон, политика, переводы).

**Боевой сайт с приёмом заявок** требует сервера: `Dockerfile` в корне запускает `server.py` (порт из `PORT`, данные в `/data`: подключите постоянный том).
Задайте `ADMIN_TOKEN`, `PUBLIC_BASE_URL=https://jaqaiym.kz` и `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`. Подойдут Railway, Fly.io, Render или любой VPS с HTTPS.
Если фронтенд останется на GitHub Pages, укажите адрес сервера в `api` и уберите `demo=True` в `tools/build_static.py` (на сервере нужен CORS для этого адреса).

### Telegram: заявки, фото и файлы

Что приходит: сообщение с карточкой заявки, затем фото одним альбомом и PDF документами. Каждый файл удаляется с диска сразу после того,
как Telegram подтвердил его получение **всеми** получателями. Сбой не дублирует то, что уже дошло: повтор досылает только недостающее
(паузы между попытками 1 мин, 2, 4 … до часа, до 40 попыток; кнопка «повторить отправку» в админке).

**Диск 1 ГБ.** Временные файлы ограничены `UPLOAD_QUOTA_MB` (500 МБ) и `MIN_FREE_MB` (150 МБ): при нехватке места загрузка файлов отключается, заявки продолжают приниматься.
Файлы без заявки удаляются через сутки (`ORPHAN_HOURS`), неотправленные через 7 суток (`UNSENT_FILE_DAYS`).

**Как создать бота и подключить получателей**

1. В Telegram откройте `@BotFather` → `/newbot` → придумайте имя и ник бота (ник оканчивается на `bot`). BotFather выдаст **токен**, это секрет.
2. Там же `/setjoingroups` → ваш бот → **Enable**, если хотите добавлять бота в группу. `/setprivacy` менять не нужно.
3. Придумайте **секретный код** подписки (длинная случайная строка, например 12 символов).
4. На хостинге задайте переменные окружения (в коде и git их не храните): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_JOIN_CODE`, `ADMIN_TOKEN`, `PUBLIC_BASE_URL`.
5. Откройте `/admin?token=…`: в блоке «Telegram» появятся ссылки для подписки.
   - **Личные сообщения:** сотрудник открывает ссылку и нажимает «Start» (или пишет боту `/join КОД`).
   - **Группа:** по второй ссылке добавьте бота в группу (или добавьте вручную и напишите в группе `/join@имя_бота КОД`).
   - Отписка: `/leave`. Отключить получателя можно и в админке.
6. Чат-id вручную указывать не нужно: сервер запоминает чаты тех, кто прислал правильный код. Общий чат с известным id по-прежнему можно задать в `TELEGRAM_CHAT_ID` (подключение: `tools/telegram_setup.py`).

Заявки, пришедшие до первой подписки, ждут получателя и уходят сразу после подключения. Чаты, где бота удалили или заблокировали, отключаются автоматически.
Проверка без настоящего токена: `python3 tools/test_telegram.py` (подставной Telegram: доставка, сбои, повторы, подписки, очистка, квота).

## Юридические документы

- `tools/legal_text.py`: текст политики конфиденциальности (рус. и каз.) и **согласия на обработку** (раздел 8 той же страницы, на него ведёт ссылка у галочки в формах). После правки: `python3 tools/gen_i18n.py`.
- Данные оператора лежат в `public/site.json` (адрес сайта, e-mail, БИН, контактное лицо, телефон) и в константах вверху `tools/legal_text.py` (наименование, адрес, плашка «Черновик»). Они же выводятся в подвале сайта. Если значение очистить, в тексте снова появится жёлтый шаблон (`<mark>`).
- Раздел 5 обещает, что данные хранятся на серверах в Казахстане (хостинг ps.kz). При смене хостинга проверьте этот пункт.
- Срок хранения в разделе 6 (1 год без договора) вписан как предложение: подтвердите или поменяйте его в обоих языках. Автоматического удаления по сроку в `server.py` пока нет.
- Когда политика утверждена юристом, поставьте `SHOW_DRAFT_NOTICE = False` в `tools/legal_text.py`, перегенерируйте (`python3 tools/gen_i18n.py`) и обновите `policy_version` в `public/site.json`.
- Шрифты хранятся в `public/fonts` (обновление: `python3 tools/fetch_fonts.py`), поэтому сайт не обращается к серверам Google.
