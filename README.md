# JAQAIYM — сайт и конструктор заявки (первый набросок)

Реализация этапов 1–3 из ТЗ (`JAQAIYM_конструктор_заявки_ТЗ_для_Санжара.md`): кликабельная анкета из 4 шагов,
реальный приём заявок и файлов, уведомление команде. Два сервера заявок с одним API и одним форматом базы: `server.py`
(Python, стандартная библиотека: локальная разработка и VPS) и `php/` (боевой вариант для общего хостинга ps.kz, где нет Python и SSH).

## Запуск

```bash
python3 server.py          # http://localhost:8123
```

- Сайт: `/`  ·  Анкета: `/request`  ·  Админка: `/admin?token=…` (токен печатается при старте и лежит в `data/admin_token.txt`).
- Заявки: `data/leads.db` (SQLite). Файлы: `data/uploads/` (не публичные; открываются только в админке по токену).
- Уведомления: без настроек пишутся в `data/outbox.log` (тестовый канал). Для Telegram задайте
  `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (общий чат команды, подключение: раздел «Telegram» ниже);
  сбой доставки не теряет заявку, сервер повторяет отправку раз в минуту (до 20 раз), причина ошибки видна в админке.

## Структура

| Путь | Что это |

| `public/request/index.html` + `js/wizard.js` + `css/wizard.css` | Анкета: 4 шага, ветки кухня / шкаф / другая мебель / бизнес, черновик, файлы, итоги |
| `public/js/common.js` | Окно быстрой заявки («Написать нам», «Нужна помощь?»), аналитика, маска телефона |

| `public/site.json` | Телефон, WhatsApp, версия политики: **заглушки (TODO)**; подставляются в шаблоны и в `window.JQ_CONFIG` |
| `public/i18n/ru.json`, `kk.json` | Тексты сайта и анкеты на двух языках. Генерируются `python3 tools/gen_i18n.py` из одного списка |
| `server.py` | Рендер страниц с подстановкой `{{ключей}}` (`/` — русский, `/kk/…` — казахский), `POST /api/leads`, `POST /api/attachments`, `/admin` |

## Языки

Русский (`/`, `/request`) и казахский (`/kk/`, `/kk/request`), переключатель в шапке. Страницы собирает сервер: в HTML стоят `{{ключи}}`,
значения берутся из `public/i18n/<язык>.json`; подписи вариантов ответа в анкете: `schema.json` (рус.) + блок `schema` в `kk.json`.
Язык клиента сохраняется в заявке (`locale`), а карточка для команды всегда на русском. **Казахские тексты нужно показать носителю языка.**
Чтобы добавить язык: новый столбец в `tools/gen_i18n.py`, значение в `LANGS` и `PAGES` в `server.py`.

## Обязательные поля анкеты (клиент и сервер проверяют одинаково)

- Шаг 1: тип заказа, где стоит мебель, планировка кухни / тип шкафа / число объектов (по типу заказа), город (только Астана и Алматы).
- Шаг 2: внешний вид; кухня: верхние шкафы, остров и техника (да / нет / не знаю); шкаф: двери и что хранить; прочая мебель: назначение; бизнес: тип объекта и задача.
- Шаг 3: размеры (или отметка «Не знаю размеры»); бизнес: количество; «Другое»: описание. Фото, бюджет, срок и комментарии необязательны.
- Шаг 4: имя, телефон и согласие на обработку данных.
Во всех блоках есть вариант «не знаю / не определился», поэтому клиента это не блокирует. Правила сервера: `required_project_fields()` в `server.py`.

## Что уже соответствует ТЗ

- Вход из любой точки (§4): `?category=`, `?project_id=`, `utm_*`, `from` подставляются сами и не спрашиваются у клиента.
- «Не знаю размеры» → `dimensions_known=false`, размеры `null`; фото/файлы необязательны.
- Скрытые поля других категорий не отправляются, но сохраняются в черновике (смена «кухня → шкаф» ничего не стирает).
- Черновик в `localStorage` (7 дней, с `schema_version`), контакты только в `sessionStorage`.
- Экран «успех» только после ответа сервера `201/200` с `lead_id`; при ошибке сети/сервера ответы и файлы остаются, повтор не создаёт дубль (`submission_id`).
- Файлы: проверка типа по содержимому на сервере, лимиты 8 файлов / 10 МБ, прогресс загрузки, превью, удаление, повтор.
- Антиспам: поле-приманка + ограничение частоты по IP. Персональные данные не попадают в URL и аналитику.
- Нет неподтверждённых цен, сроков, скидок и «бесплатного 3D».

## Решения, которые нужно принять (ТЗ §12) и временные значения

- **Бюджет**: диапазоны в `schema.json → budget` — **черновые**. Утвердить или убрать блок целиком.
- **Контакты**: телефон и WhatsApp в `config.js` — заглушки.
- **Политика и согласие**: `privacy.html` — заглушка; `policyVersion` — `DRAFT`.
- **Города**: пока только Астана и Алматы (решение владельцев). Чтобы добавить город, допишите его в `schema.json → city`, `tools/gen_i18n.py → KK_SCHEMA.city` и перегенерируйте словари.
- **Размеры** вводятся в сантиметрах, хранятся в миллиметрах (`dimensions_mm`).
- **Фото в блоках «Примеры проектов»** (кухни, шкафы, прихожие) взяты из присланных папок; по именам файлов это сток (Unsplash/Pexels), не фото ваших работ. Перед публикацией замените на свои или оставьте подпись «примеры». Свои фото ЖК остались в блоке «Для бизнеса»; ваши прежние кухня и прихожая лежат в `public/img/own/`.
- Описания проектов в карточках описательные, без названий объектов.


**Боевой сайт с приёмом заявок на хостинге ps.kz (PHP)** — следующий раздел. Запасной вариант для VPS: `Dockerfile` в корне запускает `server.py`
(порт из `PORT`, данные в `/data`: подключите постоянный том), задайте `ADMIN_TOKEN`, `PUBLIC_BASE_URL` и `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`.

### Хостинг ps.kz: версия на PHP

Тариф «XS» на ps.kz — общий хостинг Plesk: есть PHP 8.3, планировщик (cron), SQLite/MySQL, FTP и Git, но **нет Python и SSH**, поэтому `server.py` там не запустится.
Для него сервер заявок написан на PHP: тот же API, та же база, те же сообщения в Telegram. Отличия: подписчики приходят через вебхук (а не опрос),
повторы и очистку делает `cron.php`, админка открывается по паролю (cookie) вместо токена в адресе.

| Путь | Что это |
| --- | --- |
| `php/src/` | Код сервера: приём заявок и файлов, Telegram, админка (классы `Jq\…`, без сторонних библиотек) |
| `php/httpdocs/` | Что кладётся в корень сайта: `api/index.php` (единственный PHP-файл) и `.htaccess` |
| `php/bin/cron.php` | Задача по расписанию: повтор отправок, очистка файлов, срок хранения заявок |
| `php/config.env.example` | Пример настроек (`config.env` создаёт владелец, в git его нет) |
| `tools/build_php.py` | Сборка `dist/`: `httpdocs/` (сайт) и `jaqaiym-private/` (код, вне корня сайта) |
| `tools/publish_deploy.sh`, `tools/test_publish.py` | Автодеплой: выкладка сборки в ветку `deploy` (её забирает Plesk) и тест этой выкладки |
| `tools/test_php.py`, `tools/test_php_security.py` | Автотесты: функции и правила схемы (81 проверка) и «нападение» (133 проверки) |
| `tools/contract.py` | Общий тест: оба сервера (PHP и Python) ведут себя по правилам обязательных полей из `public/schema.json` |

Сборка: `python3 tools/build_php.py --noindex` (флаг закрывает сайт от поисковиков на время проверки; без него сайт открыт для индексации).

**Как выложить (Plesk → jaqaiym.kz)**

1. Загрузите содержимое `dist/` (папки `httpdocs` и `jaqaiym-private`) в корень домена. `jaqaiym-private` должна лежать **рядом** с `httpdocs`, а не внутри неё.
2. Боевые настройки создаёт скрипт на вашем компьютере: `python3 tools/make_config.py` (новый пароль админки и код подписки, токен бота берётся из локального `.env`; файл появится на рабочем столе, значения на экран не выводятся). Загрузите его в `jaqaiym-private` под именем `config.env`, поставьте права 600 и удалите файл с компьютера. Пароль сохраните в менеджере паролей, никому не пересылайте. Образец с пояснениями: `config.env.example`.
   Затем `python3 tools/make_2fa.py` (обязательно: без `ADMIN_TOTP_SECRET` админка не включается): он печатает две строки для конца `config.env` (`ADMIN_TOTP_SECRET`, `ADMIN_PATH`) и ключ для приложения-аутентификатора (Google Authenticator, Aegis, 2FAS: «Ввести ключ вручную»). Новый адрес админки будет вида `https://jaqaiym.kz/admin/<секрет>`.
3. SSL/TLS: выпустите сертификат Let's Encrypt для jaqaiym.kz (и www); перенаправление на HTTPS включено.
4. PHP: версия 8.3, `post_max_size` не меньше 12M (иначе фото больше лимита не загрузятся), `memory_limit` не меньше 128M, `max_execution_time` 60 и больше.
5. Планировщик задач: «Запустить PHP-скрипт» `…/jaqaiym-private/bin/cron.php`, раз в минуту.
6. Откройте `/admin`, войдите паролем и нажмите «подключить вебхук» (без него бот не увидит `/join`). Блок «Состояние сервера» покажет версию PHP, расширения и лимиты.
7. Отправьте тестовую заявку и проверьте Telegram. После проверки пересоберите без `--noindex` и обновите `httpdocs/`.
8. Резервное копирование: включите в Plesk (Инструменты и настройки → Резервное копирование) копирование всего домена, включая `jaqaiym-private/data` (в ней база заявок). Проверьте восстановление на тестовой копии.
9. Антивирус: в консоли ps.kz подключите ImunifyAV для сайта (он не подключён по умолчанию).

**Автодеплой.** Пуш в `main` запускает CI: если все проверки зелёные, задание `deploy` собирает сайт (`tools/build_php.py`) и кладёт результат в ветку `deploy`
(`tools/publish_deploy.sh`: обычный коммит поверх прежних, без `--force`; секреты, базы и данные в ветку не попадают, это проверяется). Plesk (Сайты и домены → Git, репозиторий «jaqaiym.git»,
режим «Автоматически», ветка `deploy`) получает вебхук от GitHub, забирает ветку и раскладывает файлы: `httpdocs/` в корень сайта, `jaqaiym-private/` рядом с ним.
`config.env`, `data/` и `logs/` в ветке нет, поэтому выкладка их не трогает. Паролей и ключей хостинга в GitHub нет.
- Индексация: пока в GitHub (Settings → Secrets and variables → Actions → Variables) не задано `SITE_INDEXING=true`, сборка идёт с `--noindex`.
- Откат: сделайте `git revert` плохого коммита и запушьте, CI выложит исправленную версию. Историю выкладок видно в ветке `deploy` и на вкладке Actions.
- Вручную: Plesk → Git → «Получить обновления» / «Развернуть». Запасной вариант без Git: `python3 tools/build_php.py --noindex`, затем загрузить содержимое `dist/` архивом.
- Доверие: тот, кто может писать в `main`, управляет сайтом. Включите двухфакторный вход в аккаунте GitHub и не давайте другим права записи без необходимости.

**Тесты и CI.** Все проверки запускаются одной командой: `bash tools/check.sh` (синтаксис PHP, Python, JavaScript, актуальность текстов i18n и три набора тестов; настоящий Telegram и токен не нужны).
Ту же команду выполняет `.github/workflows/ci.yml` на каждом `push` на GitHub, на PHP 8.3, как на хостинге: перед отправкой на GitHub запускайте её локально.
Правила обязательных полей лежат в `public/schema.json` (раздел `required`): их используют оба сервера, а анкета (`wizard.js`) хранит только соответствие «поле → место в анкете».
Добавили поле или тип заказа: правьте `schema.json`, и `python3 tools/test_php.py` проверит, что сервер принимает заявку с ответом и отклоняет без него.

**Нельзя запускать локальный `server.py` с боевым токеном бота:** он вызывает `deleteWebhook` и отключит вебхук сайта. Для разработки заведите отдельного тестового бота.

**Безопасность**

- Код, база, загруженные файлы и `config.env` лежат вне корня сайта и по ссылке недоступны; в корне один PHP-файл. Все файлы данных создаются с правами только для владельца.
- Админка: пароль не короче 16 символов (иначе она отключена), вход выдаёт cookie (HttpOnly, Secure на https, SameSite=Lax, 12 часов),
  изменения защищены токеном CSRF и проверкой Origin. Пароль не попадает ни в адрес, ни в сообщения Telegram. Смена `ADMIN_TOKEN` и кнопка «Выйти» сразу отзывают все выданные cookie на сервере.
- Двухфакторный вход и адрес админки: `ADMIN_TOTP_SECRET` обязателен, без него админка не включается (503): вход только по паролю и одноразовому коду из приложения-аутентификатора (TOTP, RFC 6238; код действует один раз),
  `ADMIN_PATH=/admin/<секрет>` переносит админку с угадываемого `/admin` на непубличный адрес. Обе строки, ключ для приложения и новый адрес печатает `python3 tools/make_2fa.py` (ничего не сохраняет).
  Отсутствие ключа 2FA или неверное значение любой из этих настроек отключает админку (503), а не ослабляет защиту.
- Защита от перебора: считаются только неудачные попытки входа и только с одного адреса (8 за 15 минут, IPv6 по сети /64). Общего счётчика нет, поэтому запереть владельца снаружи нельзя.
- Загрузки: тип определяется по содержимому (JPG, PNG, WebP, PDF), на диске файлы лежат под случайными именами, лимит 10 МБ и квота диска, после отправки в Telegram файл удаляется.
- Заявки: типы и длины проверяются на сервере, SQL только через подготовленные запросы, текст клиента в сообщении команде сводится к одной строке (служебные строки подделать нельзя), в админке всё экранируется и действует CSP с nonce.
- Вебхук Telegram принимает только запросы с секретным заголовком. Лимиты запросов по IP; в базе только необратимый хеш IP, не дольше суток.
- Страницы: CSP (скрипты только свои и с известным хешем), HSTS, X-Frame-Options, nosniff, Permissions-Policy (`php/httpdocs/.htaccess`).
- Срок хранения: заявки без договора удаляются через `RETENTION_DAYS` (365) после последнего контакта (смена статуса считается контактом); со статусом «Договор» не удаляются.
- Остаётся на владельце: сообщения с заявками лежат в чатах Telegram (бот не может удалить их спустя 48 часов), поэтому чистить рабочий чат по сроку нужно вручную; включите двухфакторную защиту в консоли ps.kz и в Telegram; держите `config.env` и пароль в менеджере паролей.

### Telegram: заявки, фото и файлы

Что приходит: сообщение с карточкой заявки, затем фото одним альбомом и PDF документами. Каждый файл удаляется с диска сразу после того,
как Telegram подтвердил его получение **всеми** получателями. Сбой не дублирует то, что уже дошло: повтор досылает только недостающее
(паузы между попытками 1 мин, 2, 4 … до часа, до 40 попыток; кнопка «повторить отправку» в админке).

**Диск 1 ГБ.** Временные файлы ограничены `UPLOAD_QUOTA_MB` (500 МБ) и `MIN_FREE_MB` (150 МБ): при нехватке места загрузка файлов отключается, заявки продолжают приниматься.
Файлы без заявки удаляются через сутки (`ORPHAN_HOURS`), неотправленные через 7 суток (`UNSENT_FILE_DAYS`).

**Как создать бота и подключить получателей**

1. В Telegram откройте `@BotFather` → `/newbot` → придумайте имя и ник бота (ник оканчивается на `bot`). BotFather выдаст **токен**, это секрет.
2. Там же `/setjoingroups` → ваш бот → **Enable**, если хотите добавлять бота в группу. `/setprivacy` менять не нужно.
3. Придумайте **секретный код** подписки (длинная случайная строка, например 12 символов).
4. На хостинге задайте переменные окружения (в коде и git их не храните): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_JOIN_CODE`, `ADMIN_TOKEN`, `PUBLIC_BASE_URL`.
5. Откройте `/admin?token=…`: в блоке «Telegram» появятся ссылки для подписки.
   - **Личные сообщения:** сотрудник открывает ссылку и нажимает «Start» (или пишет боту `/join КОД`).
   - **Группа:** по второй ссылке добавьте бота в группу (или добавьте вручную и напишите в группе `/join@имя_бота КОД`).
   - Отписка: `/leave`. Отключить получателя можно и в админке.
6. Чат-id вручную указывать не нужно: сервер запоминает чаты тех, кто прислал правильный код. Общий чат с известным id по-прежнему можно задать в `TELEGRAM_CHAT_ID` (подключение: `tools/telegram_setup.py`).

Заявки, пришедшие до первой подписки, ждут получателя и уходят сразу после подключения. Чаты, где бота удалили или заблокировали, отключаются автоматически.
Проверка без настоящего токена: `python3 tools/test_telegram.py` (подставной Telegram: доставка, сбои, повторы, подписки, очистка, квота).

## Проверка приёма заявок со страницы на GitHub Pages

Публичное демо заявки не принимает. Чтобы проверить настоящий приём, не меняя публичный сайт:

1. Локально: токен бота и пароли лежат в файле `.env` рядом с `server.py` (он в `.gitignore` и `.dockerignore`, в git не попадает). Запуск: `python3 server.py`.
2. Нужен публичный HTTPS-адрес сервера: страница на https не может обращаться к `http://localhost` с другого устройства. Для теста подойдёт временный туннель, например `cloudflared tunnel --url http://localhost:8123`; для постоянной работы — хостинг (ps.kz).
3. Откройте демо со ссылкой `?api=`, например `https://roomiestthunder.github.io/jaqaiym-site/request/?api=https://ВАШ-АДРЕС`. Внизу появится пометка «Тестовый режим», заявки и файлы уйдут на ваш сервер. Отключить: `?api=off`. Подключение действует только в этой вкладке; посетители без ссылки видят обычное демо.
4. Сервер принимает запросы со страниц из `CORS_ORIGINS` (по умолчанию github.io и jaqaiym.kz).
5. Ссылка на карточку в Telegram строится из `PUBLIC_BASE_URL`: поставьте в него адрес туннеля, чтобы ссылка открывалась с телефона.

## Юридические документы

- `tools/legal_text.py`: текст политики конфиденциальности (рус. и каз.) и **согласия на обработку** (раздел 8 той же страницы, на него ведёт ссылка у галочки в формах). После правки: `python3 tools/gen_i18n.py`.
- Данные оператора лежат в `public/site.json` (адрес сайта, e-mail, БИН, контактное лицо, телефон) и в константах вверху `tools/legal_text.py` (наименование, адрес, плашка «Черновик»). Они же выводятся в подвале сайта. Если значение очистить, в тексте снова появится жёлтый шаблон (`<mark>`).
- Раздел 5 обещает, что данные хранятся на серверах в Казахстане (хостинг ps.kz). При смене хостинга проверьте этот пункт.
- Срок хранения в разделе 6 (1 год без договора) вписан как предложение: подтвердите или поменяйте его в обоих языках. Автоматическое удаление по сроку есть в PHP-версии (`RETENTION_DAYS`), в `server.py` его нет.
- Когда политика утверждена юристом, поставьте `SHOW_DRAFT_NOTICE = False` в `tools/legal_text.py`, перегенерируйте (`python3 tools/gen_i18n.py`) и обновите `policy_version` в `public/site.json`.
- Шрифты хранятся в `public/fonts` (обновление: `python3 tools/fetch_fonts.py`), поэтому сайт не обращается к серверам Google.
